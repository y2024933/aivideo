## 1. 整體流程

```
收集建案資料 → 設定角色 DNA → 產 v1 腳本 → 4 Reviewer 並行審查 → 產 v2 修正版 → 輸出 YAML MD 檔
```

### 必要輸入資料

**必填**：
- 建案名稱、建商名稱
- 影片長度（15 / 30 / 60 / 90 / 180 秒）
- 角色 DNA（英文 prompt）+ 中文暱稱
- 故事大綱（一句話）

**選填（提供合理預設）**：
- 位置/區域、坪數範圍、總價帶
- 客群：first_buyer / upgrade / retiree / investor
- 調性：warm_family / premium / energetic / luxury / local_friendly
- 投放平台：FB / IG / YT / TikTok / 接待中心
- 必要元素、禁忌元素

## 2. 腳本結構與鏡頭配置

### 起承轉合結構（所有長度通用）

> **核心規則：場景必須先外觀再內部，不能跳切直接出現在裡面。**
> 觀眾需要「抵達」的過程才有沉浸感。

```
起 — 出發 / 抵達外觀
  角色在路上移動，遠方看到地標 → 製造懸念和期待
  觀眾先認出地標外觀，建立空間感

承 — 進入 / 體驗
  走進去的過渡（門打開、走進大廳）→ 內部廣角
  從外到內的視角轉換，帶出空間規模

轉 — 高潮 / 反差
  已經在裡面一段時間了，發生有趣的事
  搞笑、驚喜、或情緒高點

合 — 回家 / 歸屬
  回到家，安定下來，建案名 + CTA
  情緒收束，觀眾記住「住這裡的感覺」
```

### 場景轉換規則

- **先外後內**：每個新地點必須先給外觀/入口，再切內部
- **不跳切**：不能 A 地點內部 → 直接 B 地點內部，中間要有移動過渡
- **動線合理**：觀眾能理解角色怎麼從 A 到 B（走路、搭車、轉場）
- **地標辨識**：外觀鏡頭要有該地點最具辨識度的特徵（如棒球場紅色鋼骨、漢神玻璃帷幕）

### 各長度鏡頭配置

| 長度 | 鏡頭數 | Act 1 | Act 2 | Act 3 | 備註 |
|------|--------|-------|-------|-------|------|
| 15 秒 | 2 鏡 | 1 鏡（hook） | — | 1 鏡（CTA） | 極精簡，15 秒例外可低於 8 秒 |
| 30 秒 | 3 鏡 | 1 鏡 | 1 鏡 | 1 鏡（品牌+CTA 合併） | 每鏡 8-10 秒 |
| 60 秒 | 5-6 鏡 | 1 鏡 | 2-3 鏡 | 2 鏡（品牌+CTA） | 主力格式 |
| 90 秒 | 8-9 鏡 | 1 鏡 | 5-6 鏡 | 2 鏡 | YouTube / 接待中心 |
| 180 秒 | 15-18 鏡 | 2 鏡 | 11-14 鏡 | 2 鏡 | 完整版 |

### 每鏡時長指引

- **所有動畫鏡頭最低 8 秒**，不得低於此值
- Hook 鏡頭：8 秒
- 場景展示鏡頭：8-10 秒
- 情緒高潮鏡頭（蓋章、家庭）：8-10 秒
- 品牌卡（S10）：5-8 秒（純後製，不需動畫）
- CTA 卡（S11）：8-12 秒（純後製，要留時間給觀眾掃 QR / 記電話）

> **重要**：每鏡最低 8 秒是硬性規則。畫面太短觀眾看不清、感受不到情緒。
> Kling 動畫一律使用 10 秒模式（`duration: "10"`），必要時用 extend 延長。

### 品牌卡與 CTA 卡

倒數第二鏡（S10 類型）固定為品牌卡：
- 不需要 image_prompt（純後製）
- 含：建案名、英文名、slogan
- voiceover 為 slogan 朗讀

最後一鏡（S11 類型）固定為 CTA 卡：
- 不需要 image_prompt（純後製）
- 含：「立即預約賞屋」+ 地址 + 電話 + QR Code
- voiceover 為行動呼籲

## 3. 故事與台詞撰寫規則

### Hook（前 3 秒）

- 必須立刻製造懸念或反差
- 好的 hook：「咦？要去哪裡呀？」（懸念）
- 壞的 hook：「歡迎來到松竹敦富」（無聊，像簡報開場）
- 不要浪費前 3 秒在 logo 動畫

### 台詞口語化

- 寫成「角色在說話」，不是「旁白在唸稿」
- 用短句、口語、有停頓感
- 好：「空中花園...剛剛好。」
- 壞：「本建案配備頂樓空中花園，提供住戶優質休憩空間。」
- 避免文青病：不要過度詩意，建案客群不吃這套

### 音畫關係

- 旁白和畫面要互補，不要重複
- 好：畫面是空中花園 + 旁白是感受（「剛剛好」）
- 壞：畫面是空中花園 + 旁白也是「這是空中花園」

### 字幕 vs 旁白

- 字幕可以跟旁白不同，字幕偏資訊、旁白偏情感
- 範例：
  - voiceover: 「啊！原來在這裡！」（情感）
  - subtitle: 「鄰近捷運松竹站」（資訊）

### 情緒曲線

- 不能平淡一路到底，要有起伏
- 建議曲線：好奇 → 驚喜 → 舒適 → 溫暖 → 堅定 → 溫柔
- 中間插入一個「萌反差」或「幽默點」調節節奏
  - 範例：健身房鏡頭，角色玩健身球（萌反差）

### CTA 設計

- 不用弱 CTA（「期待您的光臨」）
- 用命令式 + 具體動作：「立即預約賞屋」
- 可搭配情境式：「從捷運松竹站，走到您的新家」

## 4. 角色 DNA 組合規則

### DNA 結構（英文，固定順序）

```
[體型描述], [服裝/配件], [眼睛顏色 + 負面指定],
[表情描述], [視覺風格], [光影], [構圖約束], [一致性錨點]
```

### 範例

```
a chubby and round Golden Retriever puppy,
bow tie, warm amber eyes (NOT blue),
cute and curious expression, bright sparkling eyes,
in 3D Pixar movie style, fully cartoon stylized animation,
soft volumetric lighting, cinematic depth of field,
consistent character design, same exact character
```

### 必要元素

| 元素 | 規則 | 為什麼 |
|------|------|--------|
| 體型 | 明確寫胖/瘦/圓 | AI 容易漂移體型 |
| 眼睛顏色 | 正面+負面指定 `warm amber eyes (NOT blue)` | 眼睛是最容易漂移的部位 |
| 服裝/配件 | 固定一個標誌性配件（領結、毛衣、圍巾） | 跨鏡頭辨識度 |
| 風格鎖定 | `in 3D Pixar movie style` | 防止寫實漂移 |
| 一致性錨點 | `consistent character design, same exact character` | 每鏡都要寫 |

### 漂移風險排序（高→低）

眼睛顏色 > 鬍鬚/毛髮 > 嘴型 > 體型 > 毛色

### 接受 85-90% 一致性

Flux Kontext 帶參考圖可達 85-90%。不要強求 100%，那需要 LoRA 訓練。

## 5. image_prompt 撰寫規則

### 基本結構

```
[角色描述（DNA 或 reference 指令）], [場景描述], [動作/姿勢],
[表情], [光影], [構圖], [比例]
```

### Flux Kontext 鏡頭（帶參考圖）

開頭用 `Same exact character from reference image`，不用重複完整 DNA：
```
Same exact character from reference image, standing at
the exit of a modern Taiwan MRT station, looking up with
happy excited expression, bow tie visible, ...
tall vertical 9:16 portrait composition
```

### Flux Pro 鏡頭（無參考圖 / 多角色）

直接寫完整角色描述，不用 `[DNA]` 佔位符：
```
a chubby and round Golden Retriever puppy, bow tie,
warm amber eyes (NOT blue), cute and curious expression,
...sitting on a Taiwan MRT train seat...
```

### 多角色場景（家庭畫面等）

必須套用三層 Pixar 強制，防止寫實漂移：
```
1. A 3D Pixar animated movie scene, fully cartoon stylized animation
2. NOT photorealistic
3. [人物描述] rendered in Pixar 3D animation style
```

人物+動物同框時，把要保住的次要元素放前面：
```
壞：A puppy...a young couple sitting beside...（人會消失）
好：A young Asian cartoon couple sitting on a sofa...between them, a puppy...（都在）
```

### 絕對禁止

- 不要在 prompt 裡寫中文字渲染（`text reads "XXX"`）→ 改用 `blank surface`，後製加字
- 不要用 Midjourney 參數（`--cref`、`--ar`、`--seed`）→ fal.ai 不認
- 不要寫比例數字（`9:16`）在 prompt 文字裡 → 用 API 參數 `aspect_ratio`
- 不要寫矛盾場景（「在捷運上」+「窗外是田野」）

### 場景連續性

同一住家的多鏡頭，要重複寫相同室內元素：
```
wooden oak floor, beige walls, potted monstera plant in corner,
warm evening lamp light, same modern apartment interior style
```

### 構圖

- 直式影片：`tall vertical 9:16 portrait composition`
- 橫式影片：`wide cinematic landscape composition`
- 方形：`square balanced composition`

## 6. kling_prompt 撰寫規則

### Kling 設定

- **一律使用 10 秒模式**（`duration: "10"`）
- 5 秒模式剪完只剩 ~3 秒可用，太短
- 10 秒模式剪完可用 ~7-8 秒，畫面節奏從容
- 因為片段更長，prompt 要描述更完整的動作序列（不只一個動作）

### Image-to-Video 黃金規則

> **不要重複描述圖片已有的東西（角色外觀、場景佈置），只寫「動態 + 運鏡」**

圖片已經定義了所有靜態視覺，kling_prompt 只負責告訴 AI「接下來發生什麼事」。

### 基本結構（20-40 詞，精簡）

```
[動作主體的動態] + [速度] + [環境微動] + [運鏡指令含起止點]
```

### 好的 kling_prompt（image-to-video，只寫動態）

```
slow dolly push in, subject turns head with widening eyes,
gentle wind ruffles fur, background crowd shifts softly
```

要素：運鏡（slow dolly push in）、主體動態（轉頭）、環境微動（風吹毛、人群動）。
注意：沒有重複描述角色外觀或場景，因為圖片已經有了。

### 壞的 kling_prompt

```
A cute puppy with amber eyes wearing a bow tie sitting on a train seat, the train rocks
```

重複描述了圖片已有的角色外觀和場景 → Kling 會困惑，動態品質下降。

### 更壞的 kling_prompt

```
puppy on the train
```

沒有動作方向、沒有速度、沒有運鏡 → 動畫呆滯。

### 運鏡術語

| 中文 | 英文 |
|------|------|
| 慢推近 | slow dolly in / slow push in |
| 慢拉遠 | slow dolly out / slow pull back |
| 環繞 | orbit around / circular tracking |
| 上仰 | tilt up |
| 下俯 | tilt down |
| 左右搖 | pan left / right |
| 跟拍 | tracking shot |
| 靜態 | static / locked-off |

### 配件閃現問題

角色的配件（領結、毛衣）在動畫中容易閃爍消失。解法：
在 kling_prompt 明確寫 `bow tie stays neatly in place` 或 `sweater visible throughout`

## 7. use_model 選擇邏輯

| use_model | 用途 | 角色一致性 | 選擇條件 |
|-----------|------|-----------|----------|
| `flux_kontext` | 帶角色參考圖的場景 | 高 ~85-90% | **預設首選**。只要有角色 + 不需中文字 |
| `flux_pro` | 多角色場景、角色特寫 | 中 ~70% | 家庭畫面、多人場景、第一鏡 Hook |
| `ideogram_v2_turbo` | 需要正確中文文字的場景 | 低（純文字生圖） | 畫面上要顯示中文字時 |
| `recraft_v3` | 中文備援 | 低 | ideogram 效果不好時的備選 |

### 決策流程

```
這鏡需要中文字在畫面上嗎？
  → 是 → ideogram_v2_turbo
  → 否 → 有多個角色（人+動物）嗎？
           → 是 → flux_pro（+ 三層 Pixar 強制）
           → 否 → flux_kontext（預設）
```

### 品牌卡 / CTA 卡

S10、S11 不需要 AI 生圖，由 Remotion 模板直接渲染。
不寫 use_model 和 image_prompt。

## 8. 配音與字幕規則

### 配音

- 預設語音：`zh-TW-HsiaoChenNeural`（女聲、溫暖、台灣腔）
- 可選：`zh-TW-HsiaoYuNeural`（女聲、活潑）、`zh-TW-YunJheNeural`（男聲、沉穩）
- voiceover_full 是完整配音稿，一次合成最自然（中文連讀比一句句拼接好）
- 每鏡的 voiceover 用於精確對齊動畫

### 數字處理

阿拉伯數字要轉中文，避免 TTS 讀錯：
- 「11樓」→「十一樓」
- 「3分鐘」→「三分鐘」

### voiceover_full 寫法

```yaml
voiceover_full: |
  咦？要去哪裡呀？
  啊！原來在這裡！
  空中花園...剛剛好。
  家，就是一家人在一起。
  松松...推薦！
  松松，陪你回家。
  立即預約賞屋。
  松竹敦富，期待與您相遇。
```

每句之間自然斷句，TTS 會自動處理停頓。

## 9. 法規合規規則

### 紅線（違反 = 違法，必須修正）

| 規則 | 法源 | 範例 |
|------|------|------|
| 不准用「最」字 | 公平交易法 §21 | 「最佳」「最好」「最棒」 |
| 不准用絕對化用語 | 公平交易法 §21 | 「保證」「絕對」「全台」「百分百」 |
| 不准保證投資回報 | 公平交易法 §21 | 「保證升值」「穩賺」「保本」 |
| AI 圖必須標「示意圖」 | 消保法 §22 | 全片右下角 + 公設鏡頭左下角 |
| 距離不能誇大 | 公平交易法 §21 | 用「鄰近」代替「X 分鐘」，或附「步行時間因人而異」 |
| 坪數/總價要加但書 | 消保法 §22 | 「實際以買賣契約為準」 |
| 不能點名競品 | 公平交易法 | 不能暗示性貶低 |
| 虛構代言人要標註 | 公平交易法 §21 | 「品牌虛構代言人」 |

### 罰則

- 公平交易法 §21 違反：5 萬至 2,500 萬罰鍰
- 消保法 §22 違反：罰鍰 + 消費者求償
- 廣告代理商與建商**連帶責任**

### 必要標註

```yaml
compliance_watermark: "3D／AI 示意圖｜實品以建造完成後為準"
compliance_footer:
  - "坪數及總價以實際買賣契約為準"
  - "公設規劃以實際完工及管委會規約為準"
  - "廣告核准字號：[投放前填]"
```

公設鏡頭額外加：`※公設示意圖／以建照核准為準`
角色代言鏡頭加：`※品牌虛構代言人`

## 10. YAML 輸出格式

**權威標準**：遵守 `17_Cowork_輸出模板.md`
**欄位定義**：參考 `14_MD_Schema.md`

### 完整結構

```yaml
---
project_name: 建案名稱
builder_name: 建商名稱
location: 地點
video_length_seconds: 30
target_audience: first_buyer
tone: warm_family
character_nickname: 角色暱稱
character_dna: |
  完整 DNA（英文，不用佔位符）

shots:
  - id: S01
    duration_sec: 3
    use_model: flux_kontext
    image_prompt: |
      完整 prompt（不用 [DNA] 佔位符）
    kling_prompt: |
      動畫指令
    voiceover: "旁白文字"
    subtitle: "字幕文字"
    emotion: "情緒描述"

  - id: S02
    ...

voiceover_full: |
  完整配音稿

voice_id_preferred: zh-TW-HsiaoChenNeural

compliance_watermark: "3D／AI 示意圖｜實品以建造完成後為準"
compliance_footer:
  - "坪數及總價以實際買賣契約為準"

bgm_keywords:
  - "heartwarming"
  - "gentle piano"
---
```

### 重要規則

1. `image_prompt` 裡**不要用** `[松松DNA]` 佔位符，直接寫完整描述
2. `use_model` 可選值：`flux_pro` / `flux_kontext` / `ideogram_v2_turbo` / `recraft_v3`
3. 品牌卡（S10）和 CTA 卡（S11）不需要 `image_prompt`、`use_model`
4. `emotion` 用中文
5. shots 的 `id` 格式為 `S01`、`S02`...，不能重複
6. 總時長（各鏡 `duration_sec` 加總）與 `video_length_seconds` 差距不能超過 ±2 秒

### 給 Laravel 匯入的額外欄位（選填）

```yaml
review:
  passed: true
  v2_score: 8.5
  reviewed_at: "2026-05-01"
  reviewers:
    - script: 7.5
    - prompt: 7.0
    - compliance: 9.0
    - brand: 7.5
```

`review.passed` 必須為 `true`，否則 Laravel 會拒絕匯入。

## 11. Review 流程

### 4 位 Reviewer（獨立並行，不互相溝通）

| Reviewer | 視角 | 重點檢查 |
|----------|------|----------|
| 腳本 Reviewer | 廣告影片導演 | hook 前 3 秒、節奏、CTA 強度、台詞口語化、音畫關係 |
| Prompt Reviewer | AI 視覺工程師 | 角色 DNA 一致性、prompt 翻車風險、配件閃現、use_model 正確 |
| 法規 Reviewer | 不動產律師 | 公平交易法 §21、消保法 §22、示意圖標註、距離誇大 |
| 品牌 Reviewer | 建設業品牌顧問 | 調性-客群匹配、差異化、IP 延伸性、平台適配 |

### 每位 Reviewer 輸出格式

```
通過項目：[條列]
紅旗（必修）：[條列 + 修正建議]
黃旗（建議修）：[條列]
```
