# Commit 規範

## 規則

- 當使用者要求「生成 commit 訊息」時，**只生成文字，不執行 git commit**
- 每次提供 **三個版本** 供使用者選擇
- 格式固定為：`[type] 中文描述`
- 描述下方可附修改內容，以 `-` 標注，可分行
- commit 標題應簡潔明確，避免過長或過度籠統
- 優先描述本次修改的主要目的，而非所有細節

---

## 允許的 type

| type | 用途 |
|------|------|
| `feat` | 新增功能 |
| `fix` | 修復錯誤 |
| `refactor` | 重構（不影響功能） |
| `docs` | 文件變更 |
| `chore` | 雜項維護 |
| `perf` | 效能優化 |
| `style` | 樣式或程式碼格式調整（不影響功能） |

---

## 範例

### 新增功能

**版本 1**
```
[feat] 新增工程進度時間軸區塊

- 新增 progress.html 時間軸結構
- 新增對應 CSS 樣式與 RWD 處理
```

**版本 2**
```
[feat] 實作工程進度頁面
```

**版本 3**
```
[feat] 工程進度頁面上線
```

### 修復錯誤

**版本 1**
```
[fix] 修正手機版導覽列無法關閉問題

- 調整 menu-trigger 事件綁定邏輯
- 修正 CSS transition 衝突
```

**版本 2**
```
[fix] 修正漢堡選單關閉異常
```

**版本 3**
```
[fix] 手機版選單修復
```

## 注意事項

### 1. 描述應具體明確

不好：`[feat] 更新頁面` / `[fix] 修正問題`
好：`[feat] 新增建案作品輪播區塊` / `[fix] 修正首頁影片手機版溢出`

### 2. 依據修改範圍選擇描述層級

**小範圍**（單一檔案）：
```
[fix] 修正 footer 電話連結錯誤
```

**中範圍**（多個檔案）：
```
[feat] 新增聯絡我們頁面

- 新增 contact.html 頁面結構
- 新增表單樣式與驗證
- 更新導覽列連結
```

**大範圍**（全站變更）：
```
[refactor] 重構全站導覽列結構

- 統一所有頁面 header 結構
- 調整手機版選單動畫
- 更新所有頁面的 nav 連結
```
