# 文件維護規範

## 目的

確保開發過程中遇到的常見問題、踩坑經驗、注意事項能被持續記錄，避免重複踩坑。

---

## 1. 何時應補充文件

以下情境應主動將經驗補充回 `docs/` 內：

- 開發過程中發現的常見問題（FAQ）或踩坑紀錄
- Review 過程中反覆出現的問題或易犯錯誤
- 瀏覽器相容性問題與解決方式
- RWD 調整的注意事項
- 第三方服務整合的注意事項（CDN、字型、嵌入元件等）

---

## 2. 補充到哪裡

| 內容類型 | 應補充的檔案 |
|---------|------------|
| 代碼風格相關 | `docs/code-style-rules.md` |
| Review 流程相關 | `docs/review-rules.md` |
| 開發流程、需求分析相關 | `docs/workflow-rules.md` |
| 上述皆不適用的通用注意事項 | `docs/maintenance-rules.md`（本檔案） |

---

## 3. 補充原則

- 基於實際遇到的問題，不可憑空臆測
- 記錄問題的現象、原因、解法（或規避方式）
- 保持簡潔，避免冗長描述
- 若問題已被修復或不再適用，應標記為已過時或移除
- 使用繁體中文撰寫

## 5. 持續補充機制

- Claude 在開發過程中發現值得記錄的問題時，會主動詢問是否需要補充到文件
- Review 過程中發現反覆出現的問題，會建議補充到文件
