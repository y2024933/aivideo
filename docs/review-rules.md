# Review 規則

## Review 原則

### 1. 符合既有專案風格
- 檢查命名規則是否一致
- 檢查檔案組織是否正確
- 檢查是否使用專案既有的 CSS class 或 JS 函式

### 2. 維持現有結構
- 新增功能是否放在正確的位置
- HTML 結構是否語意化
- CSS 是否在正確的區塊中

### 3. 優先沿用現有實作
- 是否重複造輪子（已有類似元件）
- 是否有現成的樣式或函式可使用

---

## Review 檢查重點

### 1. HTML 品質
- [ ] 語意化標籤是否正確使用（header, nav, main, section, footer）
- [ ] SEO 相關標籤是否完整（title, meta description, alt）
- [ ] 無障礙屬性是否適當（aria-label, role）
- [ ] 連結是否正確、無斷連

### 2. CSS 品質
- [ ] 是否有重複的樣式定義
- [ ] RWD 是否在各斷點正常顯示
- [ ] 是否使用語意化的 class 命名
- [ ] 是否有未使用的樣式殘留

### 3. JavaScript 品質
- [ ] 是否有未使用的變數或函式
- [ ] 事件監聽是否正確綁定
- [ ] 是否有 console.log 殘留
- [ ] 是否有記憶體洩漏風險（未移除的監聽器）

### 4. 效能
- [ ] 圖片是否適當壓縮
- [ ] 影片是否有適當格式與大小
- [ ] CSS/JS 是否有不必要的肥大
- [ ] 字型載入是否優化（preconnect）

### 5. 跨瀏覽器相容性
- [ ] CSS 屬性是否需要 vendor prefix
- [ ] JS 語法是否有相容性問題
- [ ] 是否在主流瀏覽器正常顯示

### 6. 共用元件一致性
- [ ] Header 在所有頁面是否一致
- [ ] Footer 在所有頁面是否一致
- [ ] Nav 連結在所有頁面是否正確

### 7. 安全性
- [ ] 外部連結是否使用 `rel="noopener noreferrer"`
- [ ] 表單是否有基本驗證
- [ ] 是否有暴露敏感資訊

---

## Review 輸出格式

```
## Review 結果

### 通過
- [項目描述]

### 需修正
- [檔案:行號] 問題描述 → 建議修正方式

### 建議
- [非必要但建議改善的項目]
```
